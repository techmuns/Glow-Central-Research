# Source collection safeguards — 24 September 2026

A failed BSE security-directory read no longer aborts the independent announcement date-index read. The collector makes the original directory request once; it does not route around source access restrictions. It uses only a valid retained registry, preserves its verification date, and keeps unknown filers under their original BSE code. Failed and incomplete directory responses never replace the published identity registry. Announcement pagination/category watermarks remain based on the actual filing reads. Company coverage is partial while the directory is unavailable, and both the source panel and operational health expose this separately from the filing capture time. If the announcement endpoint also fails, the existing captured files remain retained.

The fixed S Screen watchlist (10850427) can be read when Screener omits the export form for a genuinely empty list. Both independent management and watchlist pages must verify the exact list, controls and absence of companies. A nonempty list without an export is still refused. Populated exports must match the management count, have exactly one valid export form and stay within 8 MiB. An incomplete final membership is labelled partially synced. Collection cadence, credentials, mutation consent, removal matching and fixed account identity remain unchanged.

Verification uses local fixtures: directory HTTP 403, incomplete and malformed registries, historical BSE codes, recovery, empty and populated watchlists, missing/ambiguous exports, oversized downloads and count disagreement. No account sync or production collector is run as a test.
